# 小红书图文定时发布桌面工具设计方案

## 1. 背景与目标

本项目要做一个面向客户电脑部署的小红书浏览器自动化发布工具。第一版聚焦 Windows 桌面绿色版，客户双击启动后，可以在工具内手动新建小红书图文任务，选择账号、图片和平台定时发布时间，再手动提交到小红书创作者平台的内置定时发布。

第一版目标不是最快拼出脚本，而是建立可维护、可扩展的产品化架构。后续应能继续扩展视频发布、Mac 客户端、AI 文案生成、正式安装包、自动更新和授权系统。

## 2. 已确认范围

第一版包含：

- Windows 桌面工具。
- 绿色版压缩包交付，稳定后再做安装包。
- Electron + Python 后端架构。
- 本地单机 SQLite 数据库。
- 手动新建小红书图文任务。
- 标题、正文、标签、多图、账号、定时发布时间。
- 多账号管理，但每个任务只选择一个账号。
- 手动点击“检查并提交到小红书定时发布”。
- 默认打开可见浏览器执行发布。
- 使用小红书平台内置定时发布，不做本地到点发布。
- 首次启动自动检测并下载浏览器自动化组件。
- 下载失败时支持离线组件包兜底。
- 完整任务状态和日志。
- 视频入口预留，但第一版不实现视频发布。

第一版不包含：

- AI 自动生成文案。
- 授权、激活码、到期限制。
- 多账号批量发布同一篇内容。
- 本地定时器到点再发。
- 云端同步、多设备协作。
- Mac 打包交付。
- 视频真实发布能力。

## 3. 技术路线

采用 Electron + Python Backend：

- Electron Renderer：React / TypeScript UI，负责客户可见界面。
- Electron Main：负责窗口、托盘、启动 Python 后端、绿色版入口、后续更新能力预留。
- Python Backend：FastAPI 本地服务，负责任务 API、账号 API、环境检测、状态流转和发布编排。
- Publisher Worker：串行调用小红书浏览器自动化发布器。
- SQLite：本地任务、账号、日志、设置存储。
- Patchright Chromium：执行可见浏览器自动化。

选择该路线的原因：

- 现有小红书发布器是 Python，发布逻辑放在 Python 侧更自然。
- Electron 能提供更产品化的桌面体验。
- 前端、后端、发布器边界清晰，后续可维护性更好。
- 后续扩展 Mac 时，可复用前端和后端主体逻辑。

## 4. 模块边界

```text
apps/desktop
  Electron 主进程和渲染进程

backend/app/api
  本地 HTTP API，供 Electron 调用

backend/app/services
  任务、账号、环境检测、发布编排等业务服务

backend/app/workers
  发布工作器，控制串行执行和状态更新

backend/app/repositories
  数据访问层，第一版 SQLite，后续可替换 MySQL

backend/app/models
  数据对象和枚举定义

backend/app/integrations/xiaohongshu
  封装开源小红书发布器，隔离第三方变化

backend/app/runtime
  浏览器组件检测、下载、路径管理、日志路径管理

external/social-auto-upload-xiaohongshu
  上游小红书自动化发布器子集
```

关键原则：

- Electron 不直接调用发布器，只调用 Python API。
- Python Backend 不直接混入 UI 逻辑。
- 上游发布器封装在 `integrations/xiaohongshu` 后面，不让业务层直接依赖第三方文件结构。
- 发布任务第一版串行执行，避免多个浏览器自动化任务并发互相干扰。

## 5. 页面结构与用户流程

第一版包含 5 个主页面：

1. 任务列表
2. 新建 / 编辑图文任务
3. 账号管理
4. 发布日志
5. 环境检测 / 设置

核心用户流程：

```text
首次打开工具
→ 环境检测
→ 下载或修复浏览器组件
→ 添加小红书账号
→ 扫码登录
→ 新建图文任务
→ 填写标题、正文、标签
→ 手动选择多张图片
→ 设置平台定时发布时间
→ 保存为草稿
→ 点击“检查并提交”
→ 工具打开可见浏览器
→ 上传图文并设置小红书平台定时发布
→ 状态变为“已提交平台定时”或“失败”
```

## 6. 任务状态

任务状态使用整数编码，前端展示中文文本。

```text
草稿
待检查
待提交
提交中
已提交平台定时
失败
已取消
```

状态流转规则：

- 新建任务默认是草稿。
- 点击提交后先进入待检查。
- 字段、图片、发布时间、账号状态校验通过后进入待提交。
- 发布工作器开始执行后进入提交中。
- 小红书平台提交成功后进入已提交平台定时。
- 任一步骤失败进入失败，并记录错误信息和日志。
- 用户主动取消草稿或未提交任务时进入已取消。

发布时间必须晚于当前时间至少 2 小时。该规则前端先限制，后端再次校验。

  }

## 8. 数据库设计约束

第一版使用 SQLite，但数据库设计必须遵循用户提供的 MySQL 开发设计规范，方便未来迁移到 MySQL 8.0。

执行约束：

- 表名、字段名全部小写，使用下划线。
- 表名尽量使用单数。
- 主键统一命名为 `id`。
- 核心表必须有 `create_time` 和 `update_time`。
- 字段尽量 `not null`，业务需要时给默认值。
- 状态、类型字段使用整数编码。
- 不使用复杂 ORM，Repository 层手写 SQL + 参数绑定。
- 查询禁止 `select *`，必须显式列名。
- `insert` 必须显式指定字段名。
- 更新和删除必须带基于索引的条件。
- 索引命名使用 `idx_`，唯一索引使用 `uk_`。
- 日志类表必须设计清理策略。
- 每张表和每个关键字段必须有 comment 说明。

SQLite 不原生支持 MySQL 的 `COMMENT` 语法，因此第一版采用三层方式满足 comment 要求：

1. 设计文档中列出表和字段中文说明。
2. 数据库迁移 SQL 中使用注释描述表和字段含义。
3. SQLite 内置 `schema_comment` 元数据表记录表、字段、索引的 comment。

## 9. 数据表草案

### 9.1 `account`

表说明：小红书账号配置和登录状态。

字段：

- `id`：主键。
- `account_name`：客户自定义账号名称。
- `platform`：平台编码，第一版固定为小红书。
- `cookie_path`：账号 cookie 文件路径。
- `status`：账号状态，1-未登录，2-有效，3-失效。
- `last_checked_time`：最后一次校验时间。
- `create_time`：记录创建时间。
- `update_time`：记录更新时间。

索引：

- `uk_account_name_platform`：账号名 + 平台唯一。
- `idx_account_status`：账号状态。

### 9.2 `publish_task`

表说明：小红书图文发布任务。

字段：

- `id`：主键。
- `account_id`：账号表主键。
- `task_title`：任务标题，也是小红书笔记标题。
- `task_body`：小红书笔记正文。
- `tag_text`：标签 JSON 数组或逗号分隔文本。
- `image_path_text`：图片路径 JSON 数组。
- `schedule_time`：小红书平台定时发布时间。
- `status`：任务状态。
- `last_error`：最近一次失败原因。
- `submitted_time`：成功提交到平台定时的时间。
- `create_time`：记录创建时间。
- `update_time`：记录更新时间。

索引：

- `idx_publish_task_status`：任务状态。
- `idx_publish_task_account_id`：账号 id。
- `idx_publish_task_schedule_time`：平台定时发布时间。

### 9.3 `publish_log`

表说明：任务执行日志。

字段：

- `id`：主键。
- `task_id`：发布任务主键。
- `log_level`：日志等级。
- `log_message`：日志内容。
- `screenshot_path`：失败截图路径。
- `create_time`：记录创建时间。

索引：

- `idx_publish_log_task_id`：任务 id。
- `idx_publish_log_create_time`：日志创建时间。

清理策略：

- 默认保留最近 30 天日志。
- 失败任务关联日志不自动清理，除非用户手动清理。

### 9.4 `app_setting`

表说明：本地应用设置。

字段：

- `id`：主键。
- `setting_key`：设置键。
- `setting_value`：设置值。
- `create_time`：记录创建时间。
- `update_time`：记录更新时间。

索引：

- `uk_app_setting_key`：设置键唯一。

### 9.5 `schema_comment`

表说明：SQLite 阶段保存表、字段、索引 comment 的元数据表。

字段：

- `id`：主键。
- `object_type`：对象类型，1-表，2-字段，3-索引。
- `object_name`：对象名称。
- `column_name`：字段名；非字段对象为空字符串。
- `comment_text`：中文说明。
- `create_time`：记录创建时间。
- `update_time`：记录更新时间。

索引：

- `uk_schema_comment_object`：对象类型 + 对象名 + 字段名唯一。

## 10. 发布执行规则

第一版只使用平台内置定时发布：

- 工具不等到发布时间才发布。
- 用户点击提交后，工具立即打开浏览器，把任务提交到小红书平台定时发布。
- 提交成功后，客户电脑关机不影响平台到点发布。

执行前校验：

- 标题不能为空。
- 标题第一版按当前发布器能力限制为最多 20 个字符，前端输入时提示并限制。
- 正文可以为空，但建议填写。
- 标签最多 10 个，超过时前端阻断并提示。
- 图片至少 1 张。
- 图片路径必须存在。
- 图片格式必须受支持。
- 发布时间必须晚于当前时间至少 2 小时。
- 必须选择账号。
- 账号 cookie 必须有效，失效时引导扫码登录。

执行中：

- 默认打开可见浏览器。
- 发布工作器一次只执行一个任务。
- 每个阶段写入日志。
- 失败时保存错误信息，尽量保存截图。

## 11. 部署策略

第一阶段交付绿色版：

```text
小红书发布助手-绿色版.zip
```

解压后结构：

```text
小红书发布助手.exe
resources/
data/
logs/
runtime/
README_使用说明.html
```

启动流程：

```text
双击 exe
→ Electron Main 启动
→ 启动本地 Python 后端
→ 前端进入环境检测页
→ 检查 Patchright/Chromium 组件
→ 如果缺失，提示自动下载
→ 下载失败，提示选择离线组件包
→ 环境可用后进入任务列表
```

第一版不要求客户安装 Python、Node、MySQL，也不要求客户手动执行命令。

## 12. 风险与处理

小红书页面改版：

- 将发布器封装在 `integrations/xiaohongshu`，集中修复选择器和流程。

cookie 失效：

- 账号页显示状态，支持重新扫码登录。

客户网络无法下载浏览器组件：

- 在线下载失败后支持离线组件包导入。

图片路径或格式异常：

- 前端和后端都做校验，发布前阻断。

发布时间不足 2 小时：

- 前端时间选择器限制，后端再次校验。

验证码或风控：

- 默认可见浏览器，让客户可人工介入。

中文路径和空格路径：

- 打包测试必须覆盖中文路径、空格路径。

杀毒软件误报：

- 文档提供排查说明，后续正式安装包再考虑签名。

## 13. 验收标准

第一版验收必须满足：

- 能启动桌面工具。
- 能完成环境检测。
- 能在线下载浏览器组件；下载失败时能进入离线包兜底流程。
- 能添加至少 2 个小红书账号。
- 能扫码登录并保存账号状态。
- 能新建图文任务。
- 能填写标题、正文、标签。
- 能手动选择多张图片。
- 能保存草稿。
- 能校验发布时间必须晚于当前时间至少 2 小时。
- 能手动点击提交。
- 能打开可见浏览器完成小红书平台定时发布。
- 成功后任务变为“已提交平台定时”。
- 失败后任务变为“失败”，并记录错误日志。
- 绿色版解压到中文路径后仍能运行。
- 数据库迁移和表结构说明符合本设计的 comment 约束。

## 14. 测试策略

单元测试：

- 时间校验。
- 字段校验。
- 任务状态流转。
- Repository SQL。
- 数据库 comment 元数据写入。

集成测试：

- Electron 调用 Python API。
- Python 后端启动发布工作器。
- 任务保存、查询、提交状态变化。
- 环境检测和浏览器组件安装状态。

人工端到端测试：

- 真实小红书账号扫码登录。
- 真实图文任务提交平台定时发布。
- cookie 失效后的重新登录。
- 发布时间不足 2 小时的拦截。
- 失败截图和日志记录。

打包测试：

- 干净 Windows 环境启动。
- 中文路径启动。
- 空格路径启动。
- 无浏览器组件时首次检测。
- 网络下载失败时离线组件包导入。
