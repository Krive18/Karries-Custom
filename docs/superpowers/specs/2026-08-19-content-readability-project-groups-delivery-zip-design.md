# 内容可读性、知识库项目组与交付包设计

## 背景与目标

本次改造覆盖三个相互独立、但共同改善用户内容管理体验的方向：

1. 将视频创作记录中的提交脚本、创作要求，以及内容收藏中的 AI 内容，从大段纯文本改为结构化阅读卡片。
2. 在产品知识库的文件夹之上增加公司共享的项目组，形成“项目组 → 文件夹 → 素材”的稳定层级。
3. 将内容交付区重复的逐文件下载入口收敛为一个“一键下载全部”按钮，把视频、口播音频和字幕打包成 ZIP。

成功标准：长文本更容易浏览和复制；同一公司成员可以按项目组织素材；一次操作即可下载一个任务的完整交付物，同时不影响逐项预览、播放、查看和复制。

## 已确认的产品决策

- 项目组在公司租户内共享，不提供个人私有项目组。
- ZIP 包含任务的全部交付物：视频、口播音频和字幕。
- 视频保留“预览”，音频保留“播放”，字幕保留“查看”和“复制”。
- 移除视频、音频和字幕行内的单文件“下载”按钮。
- 不改变现有深色视觉语言和不同交付类型的分组配色。

## 方案比较与选择

### 长文本呈现

- **选用：共享的安全富文本阅读器。** 复用项目已有的 Markdown/GFM 渲染能力，为脚本和 AI 内容提供标题、段落、列表、引用、表格、代码块、复制和展开全文能力。实现成本适中，并能让多个页面保持一致。
- 备选：仅通过 CSS 增加行高、背景和间距。改动最小，但内容仍缺乏结构，无法解决长文本浏览困难。
- 备选：引入完整块编辑器。编辑能力最强，但本次需求只要求美观阅读，编辑器会显著增加依赖和数据兼容成本。

### 项目组数据建模

- **选用：独立的项目组表。** 项目组是业务层级，文件夹是内容层级，二者职责清晰，后续增加项目封面、状态或统计时不会污染文件夹模型。
- 备选：把根文件夹直接显示为项目组。迁移最快，但无法区分项目与目录，也无法稳定承载项目级元数据。
- 备选：在文件夹表增加 `folder_type`。表数量更少，但递归、重命名、删除和面包屑逻辑都需要持续判断类型，长期复杂度更高。

### ZIP 生成

- **选用：后端按任务生成完整交付 ZIP。** 服务端统一校验文件、目录结构和租户归属，浏览器只触发一次下载。
- 备选：前端依次请求所有文件再压缩。会占用大量浏览器内存，文件较大时可靠性差。
- 备选：预生成并长期保存 ZIP。重复下载更快，但需要缓存失效、存储清理和版本管理，本期没有必要。

## 一、结构化内容阅读器

### 组件边界

新增共享只读组件 `RichContentReader`，负责安全渲染、折叠、展开和复制，不负责编辑或持久化。组件接受原始字符串及展示变体：

- `script`：用于提交脚本、创作要求，强调文档式阅读。
- `assistant`：用于收藏的 AI 对话内容，沿用现有助手消息的排版语言。

现有 `AssistantMessageContent` 的 Markdown/GFM 渲染和安全链接策略下沉为共享能力。禁止直接渲染原始 HTML；外部链接继续使用安全的新窗口属性。无法解析为 Markdown 的文本按普通段落和换行显示，保证旧数据兼容。

### 交互与视觉

- 卡片头部显示内容类型、字数和“复制”按钮。
- 内容使用明确的标题层级、段落间距、列表缩进、引用样式和可横向滚动的表格区域。
- 超过 800 个字符时默认显示阅读预览，并提供“展开全文/收起”；短内容完整展示。
- 视频创作记录弹窗中的“提交脚本”和“创作要求”分别使用阅读卡片，原有任务信息、素材和交付版本保持不变。
- 内容收藏详情中的 AI 生成内容和长脚本使用同一阅读器；编辑状态继续使用原始文本输入框，避免 Markdown 展示层干扰编辑和保存。
- 复制始终复制原始文本，不复制渲染后的 DOM 文本，确保内容无损。

### 空状态与异常

- 空字符串显示“暂无内容”，不显示空白大卡片。
- 复制失败时显示现有提示样式，不阻断阅读。
- 超长表格、链接和连续字符串不得撑破弹窗或详情页。

## 二、公司共享项目组

### 数据模型

新增 `material_project_group`：

- `id`
- `tenant_id`
- `group_name`
- `created_by`
- `created_at`
- `updated_at`

约束：同一租户内项目组名称唯一；名称去除首尾空格后长度为 1–80 个字符。

`product_material_folder` 新增非空 `project_group_id`。父子文件夹必须属于同一个项目组；文件仍通过 `folder_id` 归属项目组，不在素材表重复保存项目组 ID。

迁移过程为每个已有租户创建唯一的“默认项目组”，并把该租户现有文件夹迁入其中。迁移必须幂等，重复启动不会创建多个默认项目组或改变已迁移数据。

### 权限和一致性

- 同一租户成员都可以查看、创建和重命名项目组。
- 同一租户成员都可以在项目组内创建和管理文件夹及素材，沿用现有知识库权限模型。
- 项目组只有在不包含任何文件夹和素材时才允许删除；否则返回冲突提示，避免误删团队资料。
- 所有查询和写入必须同时校验 `tenant_id`，禁止通过 ID 访问其他公司的项目组。

### API

在现有素材库接口域增加：

- `GET /api/material-library/project-groups`
- `POST /api/material-library/project-groups`
- `PATCH /api/material-library/project-groups/{group_id}`
- `DELETE /api/material-library/project-groups/{group_id}`

文件夹列表、创建和面包屑接口增加 `project_group_id` 上下文。后端不接受客户端提供的租户 ID，租户身份继续来自当前登录用户。

### 前端体验

- 产品知识库首页首先展示项目组卡片和“新建项目组”主操作。
- 项目组卡片显示名称、文件夹数量、素材数量和最近更新时间；点击进入当前文件夹视图。
- 进入项目组后，顶部面包屑显示“产品知识库 / 项目组名 / 文件夹…”。
- 项目组内保留现有新建文件夹、上传、预览、重命名和删除能力。
- 新建项目组使用小型弹窗，只要求填写名称；本期不增加封面、颜色、描述、排序和私有权限。
- 默认项目组与普通项目组使用相同操作，避免引入特殊分支。

### 错误反馈

- 名称重复：提示“该项目组名称已存在”。
- 删除非空项目组：提示“请先移走或删除项目组内的文件和文件夹”。
- 跨租户或不存在的项目组统一按未找到处理，避免泄露资源信息。
- 迁移或创建过程使用事务，防止只创建项目组但未完成文件夹归属。

## 三、一键下载完整交付包

### API 与归档结构

新增用户端接口：

`GET /api/video-edit/jobs/{job_id}/delivery/archive`

接口先验证任务属于当前租户和当前可访问用户，再汇总所有已登记的视频、口播音频和字幕。ZIP 内目录固定为：

```text
视频/
口播音频/
字幕/
```

文件名保留原始可读名称，并执行路径字符清理和同名去重，禁止 `..`、绝对路径或目录穿越。下载文件名使用“任务名称-完整交付包.zip”；任务名称不可用时回退到任务编号。

归档使用临时文件生成并通过文件响应下载，请求完成后清理临时文件。沿用现有内部素材归档的实现模式，但用户交付包使用独立服务边界，避免把内部素材权限暴露给用户端。

### 完整性规则

- 数据库声明的任一交付文件缺失时，不生成残缺 ZIP，返回“交付文件不完整，请稍后重试或联系管理员”。
- 没有任何可下载交付物时返回明确的不可下载状态。
- ZIP 生成失败必须记录任务 ID 和缺失资源类型，但日志不记录文件内容。
- 生成过程中不修改任务状态，也不重复计费。

### 前端交互

- 在交付内容卡片右上方新增主要按钮“一键下载全部（N）”，其中 N 为视频、音频和字幕的总文件数。
- 点击后按钮进入“正在打包…”状态并禁止重复点击；浏览器开始接收文件后恢复。
- 删除所有交付文件行内的“下载”按钮。
- 视频行保留“预览”，音频行保留“播放”，字幕行保留“查看”和“复制”。
- 文件名占据主要宽度，操作区统一右对齐并略向右收束；窄屏时操作区换行但不遮挡文件名。
- 各资源分组、数量标题和现有颜色保持不变，避免用户重新学习页面结构。

## 可访问性与响应式要求

- 所有图标按钮保留可见文字或无障碍名称，不能只依赖图标表达动作。
- 展开状态、打包状态和错误状态应通过文本传达，不能只依赖颜色。
- 键盘可以聚焦并触发复制、展开、预览、播放、查看和一键下载。
- 长文件名可换行或省略并提供完整标题，不能挤压操作按钮到不可点击。
- 项目组弹窗提交失败后焦点保留在名称输入框，错误信息与输入框建立语义关联。

## 测试策略

### 后端

- 数据库迁移：旧租户生成一个默认项目组；文件夹正确迁移；重复迁移幂等。
- 项目组 API：创建、列表、重命名、重名冲突、空组删除、非空组删除冲突、跨租户隔离。
- 文件夹 API：只能在指定项目组内创建和移动层级；父子项目组不一致时拒绝。
- ZIP API：包含三类目录及全部文件；文件名清理和同名去重；空交付、缺失文件、跨租户访问和目录穿越被拒绝。

### 前端

- 阅读器：Markdown 结构、纯文本回退、空内容、长内容展开、复制原文和危险 HTML 不执行。
- 视频历史与内容收藏：只读态使用阅读器，编辑态仍使用原始输入控件。
- 项目组：列表、创建、重名错误、进入项目组、面包屑和非空删除反馈。
- 交付区：只出现一个整体下载按钮；各资源保留正确的预览类操作；下载加载态和失败提示正确。

### 人工验证

- 在桌面端检查短脚本、长脚本、含列表/表格的 AI 内容和超长连续字符。
- 使用两个同租户账号确认项目组共享，使用不同租户账号确认完全隔离。
- 使用同时包含视频、音频和字幕的任务下载 ZIP，解压后逐个验证文件可用。
- 检查常规桌面宽度和窄窗口下的操作区对齐、换行及焦点顺序。

## 实施顺序

1. 建立项目组数据模型、迁移、仓储、服务和 API，并完成后端测试。
2. 改造产品知识库首页和项目组内文件夹上下文，并完成前端测试。
3. 提取共享富文本阅读器，接入视频历史和内容收藏。
4. 增加完整交付 ZIP 服务与接口，再收敛前端交付按钮。
5. 运行后端、前端和人工浏览器验证，修复回归后交付。

## 本期不做

- 私有项目组、项目组成员级权限和跨公司共享。
- 项目组封面、颜色、描述、拖拽排序、收藏和归档。
- 所见即所得脚本编辑器或对现有文本数据进行自动重写。
- ZIP 长期缓存、后台预生成、下载历史和单独计费。
