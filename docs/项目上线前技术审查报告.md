# 项目上线前技术审查报告

审查日期：2026-08-20  
审查范围：用户端、管理端、开发者端、FastAPI 后端、MySQL 8、三端静态构建、保库升级与回滚资产。

## 1. 交付结论

当前工作区已通过本地发布门禁，可以生成“生产数据库保留型增量升级包”，供上线人员自行部署。

本次交付只更新后端程序和三个前端构建产物，不携带数据库、环境变量、API Key、上传素材、Cookie、浏览器运行数据或日志。线上必须使用 `upgrade-preserve-data.sh`，禁止执行首次安装脚本或直接覆盖 `/opt/karries`。

本地验证不等同于生产环境验收。上线人员仍须在服务器确认服务、磁盘、备份、HTTPS、日志及关键业务流程。

## 2. 本轮主要功能

- Pro 视频返修按 180 算力计费，并保留真实算力流水。
- 开发者端新增付款记录，汇总算力充值和会员购买记录。
- 视频交付支持一键下载 ZIP，并展示视频生成时间。
- 产品知识库增加公司团队共享项目组、组内文件夹及用户端/管理端素材选择链路。
- 内容收藏、AI 对话和视频脚本使用富文本阅读器展示。
- 爆款解析展示原视频字幕脚本并进行字幕分析，深色模式同步适配。
- 三端生产 API 保持同源 `/api`，本地开发继续使用 Vite 代理。

## 3. 用户数据保护设计

保库升级脚本执行顺序：

1. 校验上传包的 `SHA256SUMS`；
2. 调用生产备份服务，备份 MySQL 和上传文件；
3. 校验数据库压缩包、备份清单和 SHA-256；若旧版备份脚本未生成清单，则在验证压缩包后为本次备份补建清单并立即复验；
4. 保存当前后端、前端、Python 环境与 systemd 单元作为代码回滚点；
5. 保持 `/etc/karries-api.env` 不变；
6. 保持 `/opt/karries/data`、`runtime`、`logs` 原目录不变，并校验目录 inode 未被替换；
7. 仅在新 Python 环境准备完成后短暂停止 API 和 Worker，切换代码并运行冒烟测试；
8. 切换失败自动恢复上一版应用代码。

升级脚本不会执行 `install.sh`、`seed_users.py`、`CREATE/DROP DATABASE`、`DROP USER` 或数据库导入。回滚脚本只恢复代码、Python 环境和静态文件，不自动覆盖生产数据库，避免抹掉升级后产生的新用户数据。

## 5. 已知非阻断项

- 三端 JavaScript 主包仍超过 Vite 500 kB 建议阈值；构建成功，后续可按页面拆包优化。
- Electron 开发依赖存在 1 项中危公告。Linux 服务器交付物不包含 Electron；升级到依赖范围外版本前应单独做桌面端兼容验证。
- Starlette 测试客户端存在 1 条第三方弃用提示，不影响当前测试结果。
- 当前发布内容来自含未提交修改的工作区。交付包通过内外两层 SHA-256 固定字节内容，`RELEASE-MANIFEST.json` 会记录 Git 分支、提交和 dirty 状态；后续应补做版本提交以便长期追溯。

## 6. 自行上线的强制顺序

1. 只上传新生成的 `.tar.gz` 和同名 `.sha256` 到 `/home/ubuntu`。
2. 校验外层 SHA-256，解压后再校验包内 `SHA256SUMS`；任一失败立即停止。
3. 确认 `karries-api`、`karries-publish-worker`、`nginx`、`mysql` 正常，并确认磁盘空间充足。
4. 从 `/home/ubuntu/新升级包目录` 运行 `sudo bash deploy/server/upgrade-preserve-data.sh`。
5. 不执行 `install.sh`，不复制整个目录覆盖 `/opt/karries`，不删除或重建数据库。
6. 保存脚本输出的数据库备份目录和代码回滚点，暂时不要清理旧备份。
7. 运行生产冒烟测试，检查 API、Worker 日志，并人工验证三个入口、登录、付款记录、产品知识库、爆款解析、视频返修、预览和 ZIP 下载。
8. 出现数据完整性异常时立即停止使用；优先回滚应用代码，数据库恢复必须基于明确备份点单独评估。

## 7. 回滚入口

```bash
sudo bash /opt/karries/deploy/server/rollback-preserve-data.sh
```

该命令不会自动恢复数据库。升级后已经产生的新数据将保留，避免因普通代码回滚覆盖用户数据。
