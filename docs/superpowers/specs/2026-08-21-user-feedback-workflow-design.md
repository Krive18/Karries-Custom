# 用户需求反馈闭环设计

## 目标

在用户端新增一级功能“需求反馈”，让客户提交 Bug、功能需求、体验建议或其他问题；开发者端集中处理，并在标记完成时立即向原提交用户发送站内通知。该能力只新增数据与接口，不修改、迁移或删除任何既有业务数据。

## 用户流程

1. 用户进入“需求反馈”，选择反馈类型，填写标题和详细描述后提交。
2. 用户只能查看自己提交的反馈，按更新时间倒序展示状态与开发者回复。
3. 状态分为“待处理”“处理中”“已完成”。
4. 开发者可查看全部租户反馈，按状态筛选，并填写处理回复后更新状态。
5. 当状态首次变为“已完成”时，系统在同一数据库事务内写入用户站内通知；通知点击后回到“需求反馈”。

## 数据与权限

- 新增 `user_feedback` 表，字段包括租户、提交人、类型、标题、描述、状态、开发者回复、处理人及创建/更新时间。
- 迁移仅使用 `CREATE TABLE IF NOT EXISTS`，不触碰现有表和现有行。
- 客户接口始终使用登录用户的 `tenant_id` 与 `user_id` 过滤，禁止通过 ID 读取他人反馈。
- 开发者接口使用既有 `require_developer_user` 权限保护。
- 类型仅允许 `bug`、`feature`、`experience`、`other`；标题和描述均做长度限制与首尾空白清理。
- 完成通知采用幂等更新：只有从非完成状态首次进入 `completed` 才创建通知，重复保存不会重复通知。

## API

- `POST /api/user-feedback`：客户创建反馈。
- `GET /api/user-feedback`：客户分页查看自己的反馈。
- `GET /api/developer/user-feedback`：开发者分页查看全部反馈，可按状态和关键字筛选。
- `PUT /api/developer/user-feedback/{feedback_id}`：开发者更新状态与处理回复。

## 前端体验

- 用户端侧边栏新增一级入口“需求反馈”，页面包含清晰的提交表单、状态筛选与反馈时间线卡片。
- 开发者端侧边栏新增“需求反馈”，页面提供概览数量、状态筛选、客户信息与处理抽屉/卡片。
- 浅色与深色模式都复用现有棕金色设计变量；成功提示使用绿色/中性成功态，不使用红色错误态。

## 同批 UI 修复

- 收藏稿保存成功提示改为成功态。
- Karries AI 的模型与对话模式选择器固定在同一行，保证完整标签和响应式换行。
- 用户端、管理端侧边栏支持展开/收起并记忆状态。
- 视频创作不再要求发布账号或计划时间；旧字段保留为兼容默认值 `0`。
- 创作记录中的提交素材和交付版本改为文件卡片，提供可用的预览与下载操作。
